## Frozen interfaces and conventions
- Keep one FastAPI process serving the original two GET endpoints, a nonbreaking replay timeline endpoint and optional as_of reports, plus built React/Vite assets. Use standard-library CSV/datetime/statistics, SciPy for binomial tails, plain dictionaries, and ordinary functions. Use the existing React page and SVG charts; **approved** timestamped replay reads only the bundled CSVs. Add no database, queue, real live feed, generic repository/service layer or second deployment.
- `load_dataset(path: Path) -> list[dict]` returns rows sorted by `(timestamp, station_id)`; keys are exactly `timestamp` (naive local datetime), `station_id` (nonempty string), `num_bikes_available`, `num_bikes_disabled`, `num_docks_available` (integers). Validate all rows before filtering; invalid values, timestamp or duplicate station/time raise ValueError naming the original CSV row. Reject fractional/negative counts and missing cells.
- Keep weekday records in half-open windows `[07:00,09:00)` and `[16:00,18:00)`. Missing snapshots reduce n; never resample or fill them. H-04 computes `dates=sorted(unique retained dates)` and `baseline_dates=dates[:10]` once; modules receive the same dates and must not mutate records. The report date is the latest retained date, never a different latest date for each station.
- `p_chart(baseline: list[tuple[int,int]], observations: list[tuple[int,int]]) -> dict`, with every tuple `(d,n)`, returns `{p_bar, points, warnings}`. Each point preserves input order and contains `{d,n,p,lower_count,upper_count,lcl,ucl,flagged_high,flagged_low,status,warnings}`. Invalid counts (including bools, nonintegers, d>n, negative/missing values) raise ValueError. Exclude zero-n baseline groups; unavailable basis/zero-n observations have null limits, false flags and a warning. This function knows no dates, HTTP, or ten-day rule.
- `build_availability(records, baseline_dates, target=0.10) -> {AM:{stations,charts,warnings},PM:{stations,charts,warnings}}`; `charts` maps station_id to a chart. `build_maintenance(records, baseline_dates) -> {chart,stations,as_of_date,warnings}`, where `as_of_date` is the most recent date with exact-07:00 records, or null. These modules import QC, never each other. A chart is `{baseline_dates,p_bar,points,warnings}`; dated points add ISO `date` and `p_bar` to QC fields.
- The first ten retained dates are a fixed calendar for all charts. Each station/window or network chart requires ten positive-n baseline groups within that calendar. Partial days with n>0 count; missing days do not get replaced with later event dates. The four-day numeric QC fixture remains valid because only the report modules apply the ten-day gate.
- Status is `ok`, `no_data`, or `insufficient_basis`; flags distinguish high/low within status `ok`. Unavailable numeric values use JSON null, never NaN/Infinity or an invented zero. Drop zero-n points from plotted series but keep a dated warning and a no-data dispatch row for a missing latest station/window. Suppressed limits cannot produce an in-control, special-cause, or capacity-review claim.
- `GET /api/datasets` returns `{datasets:["stable.csv","planted_events.csv","edge_case.csv"]}`. `GET /api/report?dataset=<name>` returns `{dataset,availability,maintenance,meta:{synthetic:true,exploratory:true,baseline_dates,latest_date,warnings}}`; dataset is required, unknown names return 400, missing query returns 422, invalid source rows return 422 with row detail. Resolve paths only from the allowlist. Include all station series; changing station/tab makes no additional calculation in the browser.
- Availability rows have `{station_id,date,n,d,p,empty_count,full_count,p_bar,lcl,ucl,flagged_high,flagged_low,status,empty_onset,full_onset,action,action_rank,warnings}`; each onset has `{time,affected_days,observed_days,text}` with backend-produced text. Maintenance rows have `{station_id,num_bikes_disabled,action}`. Availability sort is `(action_rank,station_id)` with rank 0 for actionable rows and 1 for OK/no-data; maintenance sort is `(-num_bikes_disabled,station_id)`.
- Dispatch uses SPEC's first match: full AND disabled at the same snapshot => collect; else high => investigate plus direction; else valid limits with neither flag and p_bar>.10 => capacity review; else empty>full => drop, full>empty => pull; else OK. Count an empty+full snapshot once in d but in both descriptive counts. Missing limits still permit measured collection/direction. Missing latest data is no-data, never OK; an empty/full tie gives no direction.
- Onset = median of first empty/full minutes on affected baseline days only; report affected / **fixed ten baseline weekdays**, plus separate observed coverage for missing station-days (normally 3/10). For an even sample average the two central minutes; floor a half-minute only for conservative HH:MM display. No affected days => null time and 'baseline timing unavailable', retaining direction without a fabricated deadline. Maintenance uses exactly 07:00; omit absent stations from both d and n and warn incomplete coverage. Never substitute 07:05. Its station list uses the most recent 07:00 date per H-10: display `as_of_date` and a stale-data warning if it precedes the global latest date; no records ever => empty list/null date.
- Use explicit package-relative imports when `__package__` is set and sibling imports otherwise. Verify root startup `python -m uvicorn app.app:app` and app-directory startup `python -m uvicorn app:app`. Scripts locate their own directory; data lookup prefers `app/data/` if bundled, otherwise repository `data/`. Register API routes before static serving, allow backend startup without assets, and serve `app/static/index.html` at `/` once built. Vite uses relative asset paths and relative `api/...` fetch URLs for the Connect prefix.
- H-03 alone owns `app/requirements.txt`: pin verified compatible SciPy, FastAPI, uvicorn, pytest and httpx versions at setup, including transitive dependencies where needed for reproducibility; deployment tooling is an environment tool unless imported by the app. Later dependency fixes go back to H-03. H-04 copies/adapts only its owned FastAPI starter files. H-05 removes the starter's browser SPC calculations/tests and renders backend numbers only.

## Numerical and dataset acceptance fixtures
- Exact binomial p-chart: `p_bar=sum(baseline d)/sum(baseline n)`; for X~Binomial(n,p_bar), alpha=.00135, `u=min{k in 0..n: P(X>k)<=alpha}`, `l=max{k in 0..n: P(X<k)<=alpha}`; UCL=u/n, LCL=l/n, high iff d>u, low iff d<l. Enumerate integer k using `binom.sf(k,n,p_bar)` and `binom.cdf(k-1,n,p_bar)`; do not substitute a normal approximation or generic confidence interval. Tail API source: [SciPy binom](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binom.html).
- Availability known answer: baseline d=[2,4,3,3], n=[24,24,24,24] gives 12/96=.125; n24 => l=0,u=9,UCL=.375; n20 => u=8,UCL=.40. n24,d10 flags high; d8 does not; equality at each count limit is unflagged. Median 07:35,07:40,07:50 => 07:40, affected/observed=3/10. Independently checked binomial tails: P(X>=10)=.0003419882809 and P(X>=9)=.001656468148.
- Maintenance known answer: baseline 10/100 => p_bar=.10; n100 => l=2,u=20,LCL=.02,UCL=.20; d25 high, d20 unflagged, d<=1 low. Low-signal text must say a decrease, not 'more bikes broke'. Baseline p_bar 0 or 1, no positive baseline exposure, or fewer than ten observed report-level baseline days => null limits and explanation. Zero-n monitored groups are not plotted. Assert flags and counts exactly; use numeric tolerance only for decimal probabilities.
- Generate deterministic synthetic `stable.csv` and `planted_events.csv`: 10 stations x 15 weekdays x 48 snapshots = 7200 rows each, common first ten days. Use fixed integer patterns and a documented seed; do not reroll data until tests pass. Residential AM-empty/PM-full and downtown opposite; a chronic station has p_bar>.10 without alarms. `edge_case.csv` has two stations over 15 weekdays with p_bar=0 for one and explicit missing snapshots for the other; report its exact resulting row count.
- Guarantee the planted maintenance signal by using total 07:00 docked bikes n=200, baseline disabled d=20 (.10), and event d=40 (.20) from day13, converting available bikes to disabled so n stays 200: u=34/UCL=.17, so 40 flags. The 10/100 ->20/100 fixture would NOT flag. Day12 PM stadium station must exceed its own UCL; choose zero disabled bikes in its full snapshots if demonstrating investigate rather than higher-priority collect. No baseline event signals; prove through QC before finalizing data.
- Required edge tests: bad row/duplicate/fraction/negative/missing input; empty input; boundaries/weekends; missing latest group and missing 07:00; n=0, p_bar=0/1, 9 vs 10 baseline days; changed n; simultaneous empty+full; action precedence and station ties; onset absent/even median; high and low flags. Stable-case demo counts high/low flags separately for baseline and monitored days, with denominator of eligible chart points. Show historical day12 on its chart even though latest dispatch is day15.

## Decisions, completion and risks
- Fixed choices: existing SPEC architecture and single statistic; explicit dictionary contracts; first ten retained dates; deterministic synthetic patterns; two independent domain writers; one API integrator; frontend after backend; coordinator-only ledger writes; no feature expansion. These are execution details within the requested scope. Target 2–4 hours for local implementation after preflight, plus deployment/access time; do not promise a two-hour finish.
- Execution is complete only when new CONTRACT H-11–H-13 each have real evidence, all inherited tests/build/browser checks pass, the replay shows no future data, the public service reproduces local results if credentials exist, and submission is independently confirmed. The final report lists task status, commands and outputs, live URL and any specific external blocker; no fabricated 'all done'. This plan supplies the handoff for a later build instruction.
- Risk 1: correlated snapshots undermine nominal alarm probabilities. Keep synthetic/exploratory labels, separate SLA from limits, and publish measured stable-case flag counts; do not claim calibrated prediction or causality.
- Risk 2: worker interface drift and off-by-one/ownership mistakes waste time. Freeze the contracts above, give one task per writer, independently verify thresholds, and require the hard API gate before the UI; route repairs to owners instead of changing neighboring modules.
- Risk 3: missing runtime, credentials or publishing rights blocks delivery. Verify Python before coding; use existing approved tooling and credentials without exposing them, prepare artifacts while access is pending, and distinguish verified local completion from deployment/submission that still needs access.
