## Statistical contract
The user is a bikeshare dispatcher deciding where and when to drop, pull or collect bikes and which stations need capacity review.
Use one exact binomial p-chart function: p_bar = sum(baseline d) / sum(baseline n); X ~ Binomial(n,p_bar), alpha=.00135; u=min{k:P(X>k)<=alpha}, l=max{k:P(X<k)<=alpha}; UCL=u/n, LCL=l/n; high iff d>u, low iff d<l. Equality is not a signal.
Availability d counts snapshots empty OR full, n counts actual snapshots, separately for each station/AM/PM; maintenance d=sum disabled and n=sum available+disabled at exactly 07:00. Never fill missing observations.
Onset is the median first empty/full time on affected baseline days; its denominator is baseline days with at least one observed snapshot for that station/window. Report coverage separately because missing snapshots can hide or delay onset.
Known answers: baseline d=[2,4,3,3], n=[24,24,24,24] gives p_bar=.125, n24 u=9/UCL=.375, n20 u=8/UCL=.40; d10 flags, d8 does not. Maintenance p_bar=.10,n100 gives l=2,u=20; d25 high,d20 unflagged,d1 low.
Keep the four-day arithmetic fixture separate from the report's ten-observed-baseline-day gate. p_bar=0/1, n=0 or insufficient baseline means null limits and explicit warnings. Signals remain exploratory; the .10 SLA is a separate target.
